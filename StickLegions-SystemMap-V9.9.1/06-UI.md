# Stick Legions system map — 06 UI

Load with Core. Health/progression emitters are defined in Health; only display behavior lives here.

## Display pipeline

- **UI-01 — References/lifecycle.** Reset and OnEnable resolve missing health/progression with GetComponentInParent, permitting root/child placement. Explicit references need not be in that hierarchy. Missing either logs an error and disables UI. Awake captures initial fill scale. OnEnable subscribes, OnDisable unsubscribes. Start marks the component started and performs the initial full refresh; the first OnEnable does not refresh, because peers may not be initialized yet. Every later OnEnable (after Start) performs a full refresh of health fill and level sprite, so changes made while disabled, for example while the unit was parked between deployments, show at once. [WM4: I10 stats UI refreshes on re-enable. WM6: I14 test 5, the health bar is correct after redeployment (the Phase 6 acceptance item; regeneration raises HP while the unit is parked, `WM-REGEN-02`)]
- **UI-02 — Health fill.** HealthChanged updates selected X/Y axis as initial scale × Clamp01(current/maximum), using zero for nonpositive maximum. Other axes retain captured initial values. Missing fill skips update. This is display only.
- **UI-03 — Level sprite.** OnLevelChanged uses the level directly as array index clamped to bounds, not level minus one. Beyond range uses last sprite; no digit composition. Missing renderer/array or empty array skips; null selected sprite leaves previous sprite unchanged. No XP/modifier subscriptions, recurring loop, public API or custom event.

## Contract card

### UnitStatsUI2D [V6, WM4, WM6]
Owns: fill/renderer/sprite references, selected fill axis, Awake-captured initial scale and a started flag.  
API: lifecycle and private refresh callbacks only.  
Events: subscribes to HealthChanged/OnLevelChanged; emits none.  
Invariants: `UI-01`, `UI-02`, `UI-03`.  
Never owns: health, level, XP, modifiers or gameplay calculations.
