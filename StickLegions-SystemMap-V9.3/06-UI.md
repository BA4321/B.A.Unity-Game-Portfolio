# UI

Load with Core. Health/progression emitters are defined in Health; only display behavior lives here.

## Display pipeline

- **UI-01 — References/lifecycle.** Reset and OnEnable resolve missing health/progression with GetComponentInParent, permitting root/child placement. Explicit references need not be in that hierarchy. Missing either logs an error and disables UI. Awake captures initial fill scale. OnEnable subscribes, OnDisable unsubscribes. Start performs initial full refresh; re-enable only restores subscriptions, so changes missed while disabled wait for an applicable event.
- **UI-02 — Health fill.** HealthChanged updates selected X/Y axis as initial scale × Clamp01(current/maximum), using zero for nonpositive maximum. Other axes retain captured initial values. Missing fill skips update. This is display only.
- **UI-03 — Level sprite.** OnLevelChanged uses the level directly as array index clamped to bounds, not level minus one. Beyond range uses last sprite; no digit composition. Missing renderer/array or empty array skips; null selected sprite leaves previous sprite unchanged. No XP/modifier subscriptions, recurring loop, public API or custom event.

## Contract card

### UnitStatsUI2D [V6]
Owns: fill/renderer/sprite references, selected fill axis and Awake-captured initial scale.  
API: lifecycle and private refresh callbacks only.  
Events: subscribes to HealthChanged/OnLevelChanged; emits none.  
Invariants: `UI-01`, `UI-02`, `UI-03`.  
Never owns: health, level, XP, modifiers or gameplay calculations.
